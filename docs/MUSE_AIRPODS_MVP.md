# Muse + AirPods MVP

Base: `origin/main` at `efc54ed81a54b43cb52fb85e7e6a4824d8dd604b`.
Branch: `feature/muse-airpods-mvp`.

Added: a bounded background Meta Muse Spark request over the existing person-mark candidate JPEG crops. Uses `MODEL_API_KEY`, `https://api.meta.ai/v1/chat/completions`, model `muse-spark-1.3`, and base64 JPEG image content. Only offered IDs and confidence >=0.9 are accepted. Ambiguity/no match selects nobody. Missing credentials or API/response failure uses the existing continuous clothing rules with explicit fallback provenance. At most eight visible candidates are sent per request. No per-frame calls, recording, new tracker, TTS service, or flight controller.

Results are rejected after cancellation, target change, track disappearance, stale reception/capture, tracker reset, or incident/session changes. A fresh simulation match binds the existing subject lock and SubjectMemory; it never starts movement or marks the result human-confirmed. Live results remain a preview proposal until human confirmation and still require the existing separate follow action and aircraft gates.

Existing: YOLO detections/track IDs, clothing measurements, candidate crops, subject memory, pursuit, SAR assessments/review, route/distance/bearing callouts, responder alert delivery, incident WebSocket, ACK events, browser speech synthesis, and native iOS AVSpeechSynthesizer with system audio routing. Native iOS was not changed.

Responder fix: refresh authoritative alert state on reconnect instead of silently skipping missed alerts; deduplicate automatic speech by incident/alert ID in memory and tab session storage. Enabling voice announces outstanding alerts once. Explicit Repeat remains available. Muting cancels queued speech. Speech uses the existing alert message, which includes server-calculated SAR guidance; no guidance is generated by Muse. Delivery means receipt, not proof that audio was audible. Web speech requires the page to remain active; it is not a background iOS notification service.

## Short demo

1. Put `MODEL_API_KEY` in the repository `.env` or exported server environment. Never put it in dashboard/browser config. Restart the backend after setting it. Without the key, the demo explicitly says fallback.
2. Start the app with `PYTHONPATH=backend:. backend/.venv/bin/python backend/scripts/run_sim_demo.py --port 8013`, or your usual configured backend command. Open `/dashboard` and start a simulation where a clearly dressed person is visible. Enter that person's clothing in Persistent target/Search or the existing person-mark assistant. With Muse configured, wait for `Muse Spark` and the selected crop/subject highlight; subsequent tracking stays local. Live DJI requires Confirm this person and separate Start follow.
3. On the responder iPhone, open the same server's `/responder?incident=INCIDENT_ID` using a reachable host address (localhost on the phone refers to the phone). Keep the page open. Select paired AirPods in iOS Control Center and tap Enable voice. Speaker is the system fallback when headphones disconnect. Optional GPS requires HTTPS; simulated responder position is available in simulation.
4. In a flood/fire/forest scenario, wait for a SAR candidate and choose Confirm + dispatch. Listen to the calculated guidance on the responder page. Tap ACKNOWLEDGE; verify the dashboard dispatch becomes acknowledged. Reconnect/reload the same responder tab: the same automatically spoken alert should not announce again. Use Repeat only for an intentional replay.

### Real Muse setup

Create a key in the [Meta Model API dashboard](https://dev.meta.ai/) under API keys, following the [official quickstart](https://dev.meta.ai/docs/quickstart). The account/key must be able to use `muse-spark-1.3`. Set `MODEL_API_KEY` in the backend process environment or the repository-root `.env`; restart the local backend. For Vercel set it in the backend's Preview environment before redeploying the PR preview, and in Production before using production. Never use a `VITE_` variable or commit the key. No OpenAI SDK or additional Muse package is required: the existing httpx dependency sends Bearer-authenticated requests to `https://api.meta.ai/v1/chat/completions` with base64 JPEG data URLs, matching the official image-understanding API. No credential was available during validation, so a real API success is still unverified. Without credentials or on API failure the UI explicitly reports fallback.

### Minimal AirPods hardware check

1. Pair AirPods with the responder iPhone; choose them in Control Center's audio output picker. Open the reachable `/responder?incident=...` page and keep it foregrounded.
2. Tap Enable voice; confirm the test announcement is audible in AirPods.
3. In the operator dashboard confirm and dispatch a flood, fire, or forest SAR candidate. Confirm the responder receives the alert and speaks its existing calculated guidance.
4. Tap ACKNOWLEDGE. Confirm the operator dashboard shows that same alert acknowledged.
5. Reconnect/reload the same responder tab and re-enable voice: the automatically announced alert must not repeat. Explicit Repeat is intentional playback.
6. Disconnect AirPods and dispatch a new alert. Verify speaker/system fallback, then reconnect and verify there is no duplicate announcement.

Physical AirPods playback is not verified by automated tests. Browser speech needs an active page; no background notification guarantee is added.
